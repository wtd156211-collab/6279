# 结构化差异（从 0 实现）

起始环境只有本说明、`samples/**` 与 `.gitignore`：差异引擎、命令行入口、期望核对与单文件 HTML 报告都从零写；
Python 3.13 标准库，不引第三方、不加构建步骤、不联网；自测用 `unittest`。

## 一、范围

做：比较两份嵌套文档，产出顺序固定的差异清单（路径 + 变更类型：新增 / 删除 / 修改 / 移动）；数组按标识键
对齐、无键时按相似度兜底；识别数组内移动与子树搬迁；把 `samples/expected/**` 逐条核对；生成数据内联、
双击即开的单文件 HTML 报告。

不做：三方合并与补丁应用；行级或字符级文本 diff；include、模板、环境变量这类语义展开；网络、数据库、
多进程；持久化格式与版本迁移；不改动 `samples/**`，除 `var/` 下的中间产物与报告文件外不写别的文件。

## 二、口径与公式

- 文档是 JSON 值，六类：对象、数组、字符串、数字、布尔、null。对象键序与空白不影响「有没有差异」，
  但决定同层差异的先后（见三）。
- 相等：数字按数学值比（`1` 与 `1.0` 相等）；布尔不是数字（`true` 与 `1` 不相等）；`null` 只与 `null` 相等；
  字符串逐码点比较。
- 节点计数：每个对象、数组、标量各算 1 个节点。
- 路径用 JSON Pointer（RFC 6901）：根记作 `/`；对象键里的 `~` 写 `~0`、`/` 写 `~1`；数组写十进制下标。
  键里不得有控制字符（U+0000–U+001F），否则算输入错误。
- 相似度 `sim(x, y) ∈ [0, 1]`，只在无标识键的数组对齐时用：
  - 类型不同 → 0；
  - 数字：`1 − |x−y| / max(|x|, |y|, 1)`；布尔、字符串、null：相等记 1，否则 0；
  - 对象：`K` 是两侧键的并集，`sim = Σ_{k∈K} w(k) / |K|`，两边都有 `k` 时 `w(k) = sim(x_k, y_k)`，
    只有一边有则 `w(k) = 0`；`|K| = 0` 记 1；
  - 数组：按下标对位，`sim = Σ_{i<min(m,n)} sim(x_i, y_i) / max(m, n)`；空对空记 1。

## 三、数据结构与流水线

深度优先递归，一个节点整体判「修改」时不再往下比。

1. 对象：按旧文档键序走——两边都有则递归，只有旧文档有则记「删除」；再按新文档键序把只在新文档的键记
   「新增」。新增、删除都以整棵子树为单位，只出一条。
2. 数组：先对齐（见下），再按旧下标升序走——配对的元素先判移动、再递归；配不上的记「删除」；最后按
   新下标升序把配不上的新元素记「新增」。
3. 其余（类型不同，或标量不相等）记「修改」。

数组对齐，条件是死的：

- **按标识键**：两侧都非空，元素全是对象、都含键 `id`、值是字符串或数字，且各自数组里 `id` 不重复 →
  按 `id` 配对，只在一边的 `id` 记新增或删除。
- **按相似度**：不满足上面条件时（含缺 `id`、`id` 重复、元素不是对象）→ 按旧下标升序贪心：每个未配对的
  旧元素，在未配对的新元素里取 `sim` 最大者，`sim ≥ 0.5` 才配对，同分取新下标最小者；配不上的旧元素记
  「删除」，剩下没配上的新元素记「新增」。值完全相同的重复元素因此按出现顺序一一对应。

移动判定：

- **数组内移动**：把配对元素按旧下标升序排开，得到它们的新下标序列 `p₁ … p_m`；第 `i` 条满足
  `i > 1 且 p_{i−1} ≥ p_i` 的元素记一条「移动」（旧路径 → 新路径），并在同一处继续递归它内部的差异。
  中间插入、删除只让下标整体平移，不会触发移动。
- **子树搬迁**：主流程产出的「删除」「新增」都指向整棵子树；收尾按清单顺序处理每条「删除」，在「新增」里
  找内容递归相等、顺序最靠前的一条配上。配成的「删除」就地改写成「移动（旧路径 → 新路径）」，那条
  「新增」从清单里去掉；配不上的保持原样。

不变量：清单顺序由两份文档唯一决定；「删除」的路径在旧文档里定位，新增、修改与移动的新路径在新文档里
定位（配对元素内部的差异用新路径）；每条只出现一次。

## 四、输入输出与文件格式

- 输入：`samples/pairs/<名>/old.json` 与 `new.json`，UTF-8 无 BOM。
- 差异清单（`samples/expected/<名>.txt`、`diff` 的 stdout）：每条一行、行尾 `\n`，字段用 TAB 分隔；
  无差异就是 0 行：

```
修改	/routes/0/backend/port
删除	/routes/3
新增	/routes/1
移动	/groups/left/probe	/groups/right/probe
```

- 库：`treediff.diff(old, new)` 返回列表，元素是 `("新增" | "删除" | "修改", 路径)` 或
  `("移动", 旧路径, 新路径)`；文本清单就是它按序渲染出来的。
- 命令行：

```
python3 treediff.py diff   <旧.json> <新.json>
python3 treediff.py check  <样例根目录>
python3 treediff.py report <样例根目录> <输出.html>
```

`diff` 只把清单写 stdout；`check` 跑遍 `<样例根目录>/pairs/*/` 与 `expected/<名>.txt` 逐字节
比对，全对时 stdout 一行 `ok=7`、退出码 0，否则打印 `mismatch=<名>`、退出码 1；`report` 先做核对再写单文件
HTML：样式与数据内联、无外链、`file://` 双击即开，按样例分节，左右并排两份结构、差异节点高亮、移动画箭头、
顶部给差异条数与四类计数，并标出该样例的核对结论；报告文件名与位置自定，交付的那份叫 `treediff.html`。

- 退出码：0 成功、1 有不符、2 输入或用法错误（stderr 一行 `error: …`）。

## 五、性能与验收口径

测试机 Windows + Python 3.13，单进程单线程；样例 7 组 14 份文档。

1. 逐条核对：`check samples` 必须 `ok=7`；报告里没有不符项。
2. 规模：`06_scale` 单侧 27,508 / 27,511 个节点，`diff` 单次 ≤ 3 秒（`time.perf_counter` 墙钟，不含解释器
   启动）。同一对文档按下标逐位置比会产出 11,933 条，正确实现只有 5 条。
3. 确定性：同一对文档连跑两遍逐字节相同；`PYTHONHASHSEED=0/1/2` 下相同；跑完 `samples/**` 不许有改动。
4. 页面：产物是单个 HTML，除内联数据外不请求任何资源；高亮的节点与箭头两端与清单一一对应，顶部计数等于
   清单里各类型条数。
5. 边界：`07_same` 只有键序与空白差异，期望是空文件；`02_insert` 在中间插入元素，不许产生移动。
6. 只用标准库，自测用 `unittest`。

## 六、样例说明

`samples/pairs/<名>/{old,new}.json` 与 `samples/expected/<名>.txt` 同名成对，期望文件是清单原文（顺序敏感）。

| 名 | 场景与关键数字 |
| --- | --- |
| `01_keys` | 键与整棵子树的增删、值修改：`true` 与 `1` 类型不同、键里带 `/` 与 `~`，11 条 |
| `02_insert` | 键控数组中间插入加尾部删除：插入不引发移动，改动元素按新下标出路径，3 条 |
| `03_move` | 数组内移动（`c` 从下标 2 到 0）与子树搬迁（`probe` 从 `left` 到 `right`），3 条 |
| `04_dups` | 无键数组：重复的 `latency` 按出现顺序配对、对象相似度 44/45 ≈ 0.978、字符串数组换序，4 条 |
| `05_deep` | 深层嵌套：最长路径 11 段，含移动元素内部的修改，3 改 1 删 2 增 1 移，7 条 |
| `06_scale` | 大结构：单侧 2.75 万节点，1 个值改动、1 次整体搬迁、1 增 1 删、顶层 1 改，5 条 |
| `07_same` | 只有键序与空白不同，期望是空文件 |

`samples/notes.md` 是现场记录，只作背景，不作为口径。
